Sysora 1.4 is a reliability release: no new feature, nine fixes found by a review of the whole code base. As before,
everything stays on your PC: no account, no telemetry, no network connection.

## Fixes

- Turning off GPU or network monitoring in Settings while that metric was being measured could leave its last value
  frozen on screen, since it was then never refreshed. The metric now stays cleared.
- On the day after a change to or from summer time, "yesterday" started an hour early or late: in the comparisons with
  yesterday (usual activity, Compare › Today vs yesterday), in "Since yesterday" and in the reference snapshots of the
  Changes page. Every day now starts at its own midnight.
- The Games, Changes and Replay pages could report that their data could not be loaded when a newer load had just
  replaced the previous one, although the data was there. On the Games page, the error message stayed on screen.
- Starting Sysora with `--page=` followed by a number made it close at once ("could not start"); it now opens the
  dashboard.
- Updating a Sysora installed for one user in a folder whose path contains an apostrophe (for example
  `C:\Users\O'Brien`) did not close the running Sysora first.
- Log files older than 14 days were only deleted when Sysora started. Sysora often runs for weeks in the notification
  area: they are now also deleted at each new day.
- When the Windows GPU counters failed to start, Sysora opened a new counter query at each attempt without closing the
  previous one, and its memory slowly grew.
- The times of the last alert evaluation and of the last save of ongoing alerts are now read and written safely by the
  threads that use them.
- If memory ran out while the process list was being read, its buffer could be released twice.

## For contributors

- New `LocalDays.Midnight` (Core) for the midnight that starts a day in a time zone, with its own UTC offset; use it
  instead of adding days to a midnight.
- Six new tests: a metric turned off while it is being collected, days around the 2026 clock changes (built-in test
  time zone `TestData.CentralEurope`, independent of the machine's time zones), and "yesterday" in the usage comparison
  on the day after a clock change.

## Update from 1.3

Download and run the new installer: it updates Sysora in place. Your settings, local history, alerts, detected changes
and game sessions are kept. Close Sysora first, or let the installer close it.

## Install

1. Download **`Sysora-1.4.0-setup-x64.exe`** (or `-arm64` for Windows on ARM) below.
2. Run it. By default Sysora is installed for all users in `Program Files` (administrator rights needed); the first
   screen also offers **Install for me only**, which needs no administrator rights.
3. Start Sysora from the Start menu.

The installer is not code-signed yet, so Windows SmartScreen may show "Windows protected your PC". Click
**More info**, then **Run anyway**. You can check the download against `SHA256SUMS.txt`.

**Requirements**: Windows 10 version 1809 or later, or Windows 11 (x64 or ARM64). Nothing else to install: the .NET
and Windows App SDK runtimes are included.
